框架定位：deepagents 是什么WHAT IS DEEPAGENTS

deepagents 不是新的运行时，而是 LangChain 官方 agent harness（运行装具）：一组围绕标准 tool-calling 循环的中间件，编译产物就是一个普通 LangGraph 图。

LangGraph 运行时

图执行 / checkpointer 持久化 / 流式 / 线程隔离——一切状态能力的地基

→
langchain create_agent

标准 agent 循环（LLM ↔ 工具调用），deepagents 的内核就是它

deepagents 中间件栈

FilesystemMiddleware（虚拟文件系统）、SummarizationMiddleware（上下文压缩）、SubAgentMiddleware（子 agent，workflow 模式不启用）、TodoListMiddleware（规划，opt-in）

→
create_deep_agent()

harness 装配入口：model + system_prompt + tools + backend + checkpointer → 返回编译好的图

关键推论：「workflow 模式」在 deepagents 里不是一个开关，而是装配选择——主 agent 以工具循环完成单篇全流程，多篇并行注册 paper_reader 子 agent 用 task 委派承担。框架与方案的关系是「主 agent 轻量闭环 + 子 agent 按需委派」。

workflow 模式的两条实现路径IMPLEMENTATION PATHS

路径 A（✓ 已选型）：create_deep_agent + paper_reader 子 agent

直接用 harness 入口，享受内置 bare stack（自动含 SummarizationMiddleware、文件工具）。注册自定义 subagents=[paper_reader] 后框架不会再自动附加 general-purpose 子 agent——主 agent 的 task 工具只认识 paper_reader，委派目标唯一、行为可控；单篇精读由主 agent prompt 约定「自己读」，多篇时约定「逐篇各发一个 task 并行」。

路径 B（备选回退）：create_agent + 按需挂 deepagents 中间件

用 LangChain 原生 create_agent，只挂 FilesystemMiddleware 等 deepagents 中间件——图里根本没有 task 委派工具，最彻底的 workflow 形态；代价是 SummarizationMiddleware 等需手动装配。bare stack 免装配、子 agent 生态完整，已选型路径 A；B 保留为回退项——若后续需要完全自控的委派链路（自定义 task 语义）可切换，两路径的 tools / backend / checkpointer 代码完全复用。

选型结论：采用路径 A——create_deep_agent 注册 subagents=[paper_reader]，主 agent 单篇自读、多篇 task 并行委派。理由：内置 bare stack 开箱即用（Summarization / 文件工具即取即用）、子 agent 生态（stream.subagents / LangSmith 追踪）完整、与 4.1 代码骨架直接对应。

4.1 Agent 工厂：模型 / prompt / 后端一次装配

# agent_factory.py —— workflow 模式：主 agent 自读单篇 + paper_reader 子 agent 多篇并行
from pathlib import Path
from langchain.chat_models import init_chat_model
from deepagents import create_deep_agent
from deepagents.backends import CompositeBackend, StateBackend, FilesystemBackend

SKILL_PATH = Path("skills/paper-reader/SKILL.md")  # 单一事实源

def build_system_prompt() -> str:
    skill = SKILL_PATH.read_text(encoding="utf-8")      # 适配版 paper-reader skill
    routing = """
## 路由规则（增量段全文见第捌节）
- 摘要级：仅调 search_papers，禁止取全文
- 细节级：AcademicPaperSearch(intent=relevant) 局部精读
- 精读/综述级：AcademicPaperSearch(intent=fulltext) 全篇阅读并写笔记到 /notes/
- 多篇：同轮逐篇各发一个 task 给 paper_reader（并行），综合各笔记作答
- 所有工具一律自己执行，禁止委派子任务
"""
    return skill + "\n\n" + routing  # 前置到内置 prompt，不替换

def create_workflow_agent(checkpointer=None):
    model = init_chat_model(                  # 内网 OpenAI 兼容接口
        CFG.llm_model, model_provider="openai",
        base_url=CFG.llm_base_url, api_key=CFG.llm_api_key)
    disk = FilesystemBackend(root_dir="/data/cache", virtual_mode=True)
    return create_deep_agent(
        model=model,
        system_prompt=build_system_prompt(),
        tools=[search_papers, AcademicPaperSearch],
        subagents=[paper_reader_spec()],       # 多篇并行精读（见 4.3）
        backend=CompositeBackend(default=StateBackend(),
                                 routes={"/papers/": disk, "/notes/": disk}),
        checkpointer=checkpointer,            # 会话持久化（见 6.2）
    )

4.2 两个论文工具：落盘隔离的关键

import httpx
from langchain_core.tools import tool

client = httpx.AsyncClient()  # 复用连接池；ACADEMIC_BASE / ACADEMIC_TOKEN 来自配置

@tool
async def search_papers(query: str, top_k: int = 10, time_range: str = "") -> str:
    """按关键词搜索论文，返回候选列表（标题/作者/年份/摘要/docid）"""
    results = await search_client.search(query, top_k, time_range)
    return render_candidates(results)   # 仅元信息，控制在 ~3k token

@tool
async def AcademicPaperSearch(query: str,
                          intent: str = "fulltext",
                          question: str = "") -> str:
    """获取论文全文或相关片段。query=docid/fileid；intent=relevant 时须传 question"""
    htype = "docid" if is_docid(query) else "fileid"
    payload = {"query": query, "type": htype, "stream": False,
               "options": ({"intent": intent, "question": question}
                          if htype == "docid" else {"splitter": 1})}
    # 经 academic_service 服务内接口请求获取（Bearer 鉴权）：
    #   POST /api/v1/navigator/query
    #   fileid → doc_fulltext 全文（splitter=1 小块，客户端拼接）
    #   docid  → /search：intent=fulltext 拼全文 / relevant 重排片段
    resp = await client.post(f"{ACADEMIC_BASE}/api/v1/navigator/query",
                           json=payload, timeout=60,
                           headers={"Authorization": f"Bearer {ACADEMIC_TOKEN}"})
    text = extract_paper_text(resp.json(), htype)  # 全文拼接 / segments 提取
    path = await cache_to_disk(query, text)   # 写入挂载卷，命中缓存则跳过
    # 关键技巧：FilesystemBackend 的 root_dir 与 /data/cache 同一块物理盘，
    # 工具直接写文件 == 写入虚拟文件系统的 /papers/{hash}/
    return outline_and_stats(path)        # 只回章节目录+token统计

agent 之后的阅读动作全部走内置 read_file(path, offset, limit) / grep——正文按需分段进上下文，这正是「全文永不进主上下文」的落地。

4.3 多篇并行：注册 paper_reader 子 agent + task 并行委派

def paper_reader_spec() -> dict:                # 字典式 SubAgent 定义
    return {
        "name": "paper_reader",
        "description": "精读单篇论文并产出结构化笔记到 /notes/，"
                      "输入论文句柄与用户问题。一次只读一篇。",
        "system_prompt": build_system_prompt(),  # 同一份 SKILL.md
        "tools": [AcademicPaperSearch],             # 仅取文；读写文件由中间件提供
    }

agent = create_deep_agent(
    model=model,
    system_prompt=build_system_prompt() + ROUTING,  # 路由规则含多篇策略
    tools=[search_papers, AcademicPaperSearch],
    subagents=[paper_reader_spec()],              # 注册后不再自动挂 general-purpose
    backend=..., checkpointer=...,
)
# ROUTING 中写明：多篇时在同一轮里逐篇各发一个 task 调用（并行执行），
# 全部返回后读 /notes/ 综合作答；单篇精读则主 agent 自己执行。
上下文隔离：每个子 agent 拥有独立的消息列表——单篇全文细节留在子 agent 上下文内，主 agent 只拿到笔记摘要 + /notes/ 路径；某篇阅读失败以 task 结果形式返回错误信息，主 agent 可降级标注，不中断整批。进度可用 stream.subagents 分别订阅每个子任务。

4.4 服务接入：sessionId 即 thread_id

# server.py —— FastAPI 接入层
@app.post("/v1/agent/chat")
async def chat(req: ChatRequest):
    config = {"configurable": {"thread_id": req.sessionId}}
    result = await agent.ainvoke(
        {"messages": [{"role": "user", "content": req.message + paper_refs(req)}]},
        config=config)
    return {"answer": result["messages"][-1].content}

长文本防线的技术参数LONG-CONTEXT DETAILS

方案肆节的四层防线在框架层的精确行为（官方文档核实值）：

机制触发与行为
大工具结果自动驱逐工具输出超过阈值时自动卸载到 /large_tool_results/，消息中留占位符，agent 可 read_file 分段读回——即使工具忘了「只回目录」也有兜底
历史自动摘要上下文达模型 max_input_tokens 的 85% 触发：LLM 生成结构化摘要替换旧历史，保留 10% 近期消息；原文全文写入 /conversation_history/ 可回查；模型 profile 缺失时回退 170k token / 保留 6 条
溢出应急任何模型调用抛 ContextOverflowError → 立即摘要压缩后自动重试，请求不失败
按需压缩工具可加 create_summarization_tool_middleware(model, backend) 提供 compact_conversation 工具，让 agent 在任务间隙主动压缩（与自动摘要共享引擎）
流式过滤摘要步骤产生的 token 可按 metadata.lc_source == "summarization" 过滤，不混入正文输出
与方案预算的衔接：单篇 ≤20 万 token 的阅读预算由「主 agent 模型上下文窗口 ≥20 万」保证；即便超出，上述机制保证的是不崩（摘要压缩），而阅读质量靠分档路由在超限前就把全文消化成笔记。

6.1 虚拟文件系统路由

disk = FilesystemBackend(root_dir="/data/cache", virtual_mode=True)
backend = CompositeBackend(
    default=StateBackend(),                        # 会话态 + 框架内部路径
    routes={"/papers/": disk, "/notes/": disk})  # 跨会话缓存

框架自动写入的内部路径（/large_tool_results/、/conversation_history/）落在 default 即 StateBackend——这正是官方推荐 Composite 包裹的原因：内部产物随会话消失，项目数据长期留存，互不污染。

6.2 checkpointer 选型

环境实现说明
开发InMemorySaver / AsyncSqliteSaver零依赖起步；重启即丢（可接受）
生产AsyncPostgresSaver（langgraph-checkpoint-postgres）thread 状态 / 会话记录全量持久；TTL 清理走定期任务

6.3 TTL / LRU：框架无内置，需自建清理任务

deepagents 不提供缓存过期——按方案柒节的分层表，落一个 cron 任务：/data/cache 按目录 mtime 清理（全文 7–30 天、笔记同 TTL）、checkpointer 会话表按 TTL 清理（24–72 小时）；容量上限用简单的目录大小统计 + LRU 淘汰。

风险与注意事项清单RISKS & NOTES

事项说明与对策
FilesystemBackend 安全告警官方明示不建议 Web 服务裸用（agent 可读写宿主文件）。本方案属官方列举的可接受场景「挂载持久卷」且三重防护：virtual_mode=True 路径沙箱、CompositeBackend 限定仅 /papers/ /notes/ 可落盘、agent 无 shell 工具。更严格可换 StoreBackend（Postgres 存储，跨 thread 持久）
子 agent 失败与超时子 agent 异常以 task 工具结果形式返回（不炸主循环），主 agent 感知后降级；应用层仍需并发信号量（限制同时派发数）与单篇超时兜底——deepagents 不内置子 agent 超时
system_prompt 是前置非替换内置 prompt（文件工具指引等）始终存在；skill 适配时不要重复描述文件工具用法
版本陷阱Python 包 deepagents 当前 0.7.x（≥3.11）；2025 年旧教程的 instructions= 参数、旧式 CompositeBackend lambda 写法均已过时，以 docs.langchain.com 为准
摘要的不可逆性历史压缩后旧消息从工作记忆移除（原文仍在 /conversation_history/）——依赖历史细节的追问需靠 read_file 回查，prompt 中应提示这一路径
内网模型需支持 function callingtool-calling 循环是硬依赖；选型时验证内网 OpenAI 兼容网关的 tools 参数与流式行为

Prompt 全集PROMPT COLLECTION · 单一事实源

主 agent 与 paper_reader 子 agent 的 System Prompt 同源于「适配版 SKILL.md + 增量段」，服务启动时由 build_system_prompt() 读取拼装。以下给出全部增量段的完整文本与子 agent 完整定义（skill 本体的 6 处适配见方案伍节）。

8.1 主 agent System Prompt：拼装结构与增量段全文

# system_prompt 拼装公式（前置到 deepagents 内置 prompt，不替换）
[适配版 SKILL.md 全文]   # 阅读方法学：三档深度 / 论文类型 / 证据映射 / 诚实规则
+ ROUTING_FULL           # 意图分档路由（下文全文）
+ OUTPUT_STYLE_FULL      # 输出与引用规范（下文全文）

# ============ ROUTING_FULL ============
## 意图分档路由规则
判断用户问题档位，从上到下匹配，宁低勿高（能摘要级不细节级，能细节级不精读级）：

- 摘要级（论文列表 / 方向概览 / 找候选）：
  仅调 search_papers，基于标题与摘要作答，禁止取全文。
- 细节级（实验设置 / 某公式 / 某表格 / 核对某论断）：
  AcademicPaperSearch(intent="relevant", question=用户原话)，
  基于返回片段作答；片段不足以回答时回退 fulltext。
- 精读级（理解全文 / 方法主线 / 证据边界 / 批判分析）：
  单篇 → 自己执行 AcademicPaperSearch(intent="fulltext")，
  按 SKILL 工作流通读并写笔记到 /notes/ 后作答。
- 多篇（≥2 篇且需精读）：
  同一轮内逐篇各发一个 task 给 paper_reader（并行执行），
  全部返回后读 /notes/ 综合作答；一次最多 5 篇，
  超出请用户圈定优先级。
- 候选确认（搜索结果 ≥3 篇且用户未锁定目标）：
  列候选（编号 / 标题 / 作者 / 年份 / 一句话简介）请用户选择，本轮到此为止。

# ============ OUTPUT_STYLE_FULL ============
## 输出与引用规范
- 关键论断（数字 / 方法 / 图表结论）→ 位置级引用：[2] §3.2 式(4) 表 3
- 一般论述 → 论文级引用：[1]
- 文末「参考文献」仅列：标题 + 涉及章节；禁止出现 docid / fileid
- 严格区分「作者声称 / 证据显示 / 基于证据的解释」三种表述
- 无法定位 → 写「正文未提供可靠位置」；论文未报告 → 写「论文未报告」；禁止虚构
- 你的回答是最终交付：结构完整、可直接呈现，语言跟随用户提问语言

8.2 paper_reader 子 agent：完整定义

paper_reader = {
    "name": "paper_reader",
    "description": "精读单篇论文并产出结构化笔记到 /notes/。输入：论文句柄"
                 "（docid / fileid）+ 用户问题。一次只读一篇；不搜索、不评分、"
                 "不与用户对话。返回：笔记路径 + ≤500 字核心结论摘要。",  # 主 agent 据此决定何时委派
    "system_prompt": build_system_prompt() + SUBAGENT_EXTRA,  # 同源 skill + 专项约束
    "tools": [AcademicPaperSearch],  # 文件读写由 FilesystemMiddleware 注入
}

# ============ SUBAGENT_EXTRA（专项约束全文） ============
## 子 agent 专项约束
- 你是一次性任务执行者：把成果写入 /notes/{句柄}.md，不与用户对话
- 笔记模板（固定结构）：论文定位 / 一句话结论 / 研究问题与贡献 /
  方法主线 / 关键结果（每条带位置引用）/ 证据边界与局限 / 后续阅读建议
- 每条关键结论必须附「证据引文 + 位置（§章节 / 式 / 表）」，缺一不可
- 全文超预算时：先读章节目录定位，跳过无关章节，并在笔记开头声明覆盖范围
- 失败即报告：取不到全文 / 内容明显残缺时，如实返回失败原因，禁止编造

8.3 工具描述：LLM 可见的 prompt（docstring 全文）

search_papers(query, top_k=10, time_range="") -> str
"""按关键词搜索学术论文。返回候选列表：编号 / 标题 / 作者 / 年份 /
venue / 摘要前 200 字 / docid。适用于：论文列表、方向调研、候选确认。
不返回全文。query 取用户原意关键词（中英文皆可）；时间限定写入
time_range（如 "1y"、"2024-"）。"""

AcademicPaperSearch(query, intent="fulltext", question="") -> str
"""获取论文内容（内部经 academic_service 服务接口请求：
POST /api/v1/navigator/query，Bearer 鉴权）。query = 论文句柄
（docid 或 fileid），禁止传标题或自然语言问题。
intent="fulltext"：请求全文并落盘 /papers/，返回章节目录 + token
统计，之后用 read_file(offset, limit) 分段阅读。
intent="relevant"：必须传 question（用户原话），由 academic_service
的重排管道返回与问题相关的正文片段，用于细节级局部精读；片段不足
以回答时改用 fulltext 重取。注：relevant 仅 docid 路径支持，fileid
恒为全文（小块 splitter 拼接）。"""
注入语义提醒：system_prompt 是前置而非替换——内置 prompt（文件工具指引等）始终生效，增量段不要重复描述文件工具用法；SKILL.md 任何改动重启服务即生效，无需发版。
