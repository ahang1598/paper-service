整体架构ARCHITECTURE · FOUR LAYERS

┌─ 接入层 ─────────────────────────────────────────────┐
│ sessionId + interaction → thread_id 会话映射               │
│ 服务持有完整对话记录（候选列表 / 已选论文 / 已读笔记）        │
├─ Agent 层 ────────────────────────────────────────────┤
│ 主 agent：意图理解 → 路由分档 → 搜索/取文 → 综合成稿   │
│   单篇：主 agent 内闭环精读（System Prompt 含适配版 skill） │
│   多篇：每篇派一个 paper_reader 子 agent 并行精读   │
│   └─ 虚拟文件系统：/papers/ 全文缓存  /notes/ 阅读笔记      │
├─ 工具层 ─────────────────────────────────────────────┐
│ search_papers(query, top_k, time_range)     关键词搜索      │
│ AcademicPaperSearch(query, options)          全文落盘/片段   │
│   └─ options.intent: fulltext | relevant(+question)  │
├─ 数据层 ─────────────────────────────────────────────┐
│ 搜索上游 + academic_service /navigator/query（全文·片段）    │
│ + 磁盘缓存（同一论文句柄只取一次）                           │
└──────────────────────────────────────────────────────┘
设计原则：全文永不进入主 agent 上下文——工具只返回章节目录与 token 统计，正文留在虚拟文件系统，按阅读档位局部或全篇消化；单篇全流程在主 agent 内闭环，多篇靠子 agent 上下文隔离与并行。

三个核心场景CORE SCENARIOS

1
摘要直答“帮我查 mamba 最近的论文”

search_papers 搜索 → 基于标题 / 摘要 / 元信息直接组织回答，不取全文。轻量快速。

2
精读问答“精读《xxx》，讲讲实验过程”

论文句柄落盘 → 按意图分档阅读（局部精读 / 全篇精读）→ 带位置引用的综合答案；多篇派 paper_reader 子 agent 并行精读。

3
候选确认“查询 xxx 方向的论文”

搜索 → 答案中列出候选（标题/作者/年份）→ 用户经小艺回话选择 → 会话记录驱动触发精读，无需重传状态。

肆

长文本处理LONG-CONTEXT · 核心竞争力

论文全文 1–5 万 token，是本服务必须正面化解的核心矛盾。四层防线层层递进：

落盘隔离

全文写入虚拟文件系统，工具只返回章节目录 + token 统计；deepagents 自动「大工具结果驱逐」机制兜底。

意图分档路由（主 agent 自主判断）

摘要级 → 不读全文；细节级（“实验用的什么数据集”）→ relevant 模式定位段落局部精读；精读/综述/批判级 → 主 agent 内进入全篇精读流程。路由规则约 20 行，随 prompt 迭代。

子 agent Map-Reduce 综合

单篇：主 agent 在自身上下文内完成全篇阅读（预算 ≤20 万 token）；多篇：每篇论文派一个 paper_reader 子 agent（独立上下文窗口），一轮并行派发，各自产出结构化笔记写入 /notes/，主 agent 只综合笔记（一次上限 5 篇）。追问时笔记与全文缓存直接复用，零重复成本。

阅读方法学内置

三档阅读深度（语境速读 / 分析精读 / 技术精读）+ 论文类型自适应重点 + 证据映射规则——全部来自已沉淀的 paper-reader skill（见第伍节）。

会话与存储机制SESSION · STORAGE · LIFECYCLE

会话：服务持有对话状态

sessionId 映射 deepagents thread_id，checkpointer 持久化全对话状态（对话历史、候选列表、已选论文）。会话内追问——“第 2 篇”“再讲讲它的消融实验”——由会话记录驱动，无需外部重传状态。

存储：按生命周期分四层，虚拟文件系统 ≠ 数据库

数据存放位置生命周期说明
论文全文
/papers/{id}		磁盘缓存层（内容寻址：句柄哈希）TTL 7–30 天 + LRU 容量上限跨会话跨用户复用，同一句柄只调一次上游；经 CompositeBackend 将该路径路由至本地磁盘持久层
阅读笔记
/notes/{id}		磁盘缓存层（论文 + 阅读档位寻址）同全文 TTL论文派生物，跨会话复用可省去重复的 LLM 精读调用——LLM 成本大头
会话状态
（对话 / 候选 / 规划）		checkpointer（thread 级）TTL 24–72 小时会话结束 ≠ 立即释放：数据留存至 TTL 过期或显式清理；生产用 Sqlite / Postgres checkpointer，dev 可用内存型
reranker 片段结果工具层响应缓存 (docid, question_hash)TTL 1–7 天不进虚拟文件系统——它是数据管道中间态，agent 只需最终 segments；进 VFS 反而污染 agent 工作区
关键澄清：deepagents 虚拟文件系统默认 StateBackend 下，文件随 thread 状态存于 checkpointer——会话结束不会立即释放，而是随 TTL 过期清理；跨会话复用（全文 / 笔记）必须经 CompositeBackend 路由到磁盘持久层。reranker 的 chunks / 打分等中间数据生命周期 = 单次工具调用，留在工具层缓存即可，与虚拟文件系统无关。
