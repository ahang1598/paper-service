# Paper Reader（论文文本阅读助手）

## Overview

根据用户提供的论文文本，回答用户的各类读论文需求，并把结果以结构化 Markdown 笔记的形式写入**当前工作目录**。核心原则：一切论断严格基于所给文本，文本没有的内容明确说明"未提及"，绝不脑补。

## 工作流程

### 1. 获取并通读论文文本

- 用户给了文件路径 → 用 Read 读取；给了粘贴文本 → 直接使用。
- 文本较长时分段读完，**必须读完全部内容再作答**，禁止只读开头就下结论。
- 若用户只提供了摘要或部分章节，先在回答开头注明"当前仅基于部分内容，结论覆盖范围受限"。
- 扫描件/图片型 PDF 无文本层时不做 OCR，提示用户先转文本。

### 2. 识别需求类型

将用户需求归入以下三类（可组合，一次任务可产出多份笔记）：

| 类型 | 典型说法 | 产出文件后缀 |
|---|---|---|
| 精读笔记 | 总结这篇论文 / 帮我精读 / 做笔记 | `-精读笔记.md` |
| 问答解读 | 论文里的 X 是什么意思 / 实验怎么做的 | `-问答.md` |
| 批判性分析 | 有什么创新点和局限 / 实验充分吗 / 帮我挑毛病 | `-批判性分析.md` |

用户未明确类型时：问句形式 → 问答；要求"总结/笔记" → 精读笔记。

### 3. 生成笔记内容

读取 [references/note-templates.md](references/note-templates.md)，按对应类型的模板生成 Markdown。通用要求：

- 全程使用简体中文；专业术语保留英文原词（如 Transformer、ablation）。
- 关键论断标注出处（章节名 / 原文短句引用），格式：`(§3.2)` 或 `> 原文引用`。
- 文本未提及的信息（如代码链接、作者单位细节）写"文中未提及"，不得编造。
- 精读笔记控制在一屏可读的长度，突出"这篇论文解决了什么、怎么解决的、效果证据、有何局限"这条主线。

### 4. 写入当前目录

- 写入位置：**当前工作目录**（cwd），不建子目录，除非用户另有要求。
- 文件命名：`{论文slug}-{类型}.md`。论文 slug 取标题前几个关键词的短横线小写形式（如 `attention-is-all-you-need`）；用户给了简称就用用户的。
- 同一论文的后续问答：**追加**到已有的 `-问答.md` 文件末尾，每轮问答标注日期（`## 2026-08-13 问答`），不要覆盖历史记录。
- 写入已存在的同名笔记文件前，先 Read 再 Edit/追加，避免误覆盖。

### 5. 交付

- 写完文件后调用 present_files 把生成的 .md 文件展示给用户。
- 回复中用几句话概括笔记核心结论，不重复粘贴全文。
