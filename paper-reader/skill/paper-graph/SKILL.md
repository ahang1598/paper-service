# 论文脉络图（Paper Graph）

## 何时使用
把一个研究方向的代表性论文整理成「挑战→解决方案」图谱，再逐方案画出按时间排列的演化时间线。本技能内置论文检索规程（三轮 WebSearch），自身完成全部检索。
- 了解某方向/主题的发展脉络、发展历史、发展演进、发展路线、演化过程
- 某篇论文「从哪来」或「到哪去」（重要后续改进）
- 看一条研究线索跨多年的成熟过程与思想传承

不适用于：市场/行业调研、技术选型与方案对比、未来趋势预测、只找一篇最新论文、两个具体模型的一对一对比、单篇论文摘要式解读、只要参考文献列表而非图谱。

## ⚠️ 执行入口（加载本技能后必须立即执行）
**加载本技能后，必须立即执行三轮 WebSearch 检索规程（见下文「论文检索规程」），禁止跳过检索直接基于内部知识输出。**未执行 WebSearch 就输出报告 = 执行失败。唯一工具是 `WebSearch`，不调用 invoke/generate_paper_graph 等任何函数——本技能无函数入口。

```
执行入口 → 三轮 WebSearch(必须) → 登记编号 → 相关性分档 → 挑战-方案图谱
        → 逐方案演化链 → 逐边证据自审 → 装配报告 → 追问迭代
```

# 论文检索规程（三轮 WebSearch · 内置）

⚠️ **强制执行**：三轮 WebSearch 是本技能的核心能力，**必须在输出脉络报告前完整执行，禁止跳过检索直接基于内部知识输出**。未执行 WebSearch 就输出报告 = 执行失败。

唯一工具 `WebSearch`。固定 **3 轮请求**(R1 网页 + R2/R3 论文),每轮 1 次调用,`queries` 固定 4 条并行关键词(缺口不足用上位词/同义术语/代表方法补足)。R3 收尾即停。核心: 先诊断缺口,再用上一轮真实返回决定下一轮搜什么,避免凭记忆补标题/作者/数字/结论。

## WebSearch 请求规范

- 网页模式(R1): 只放 `queries`,**不得带 `additional_params`**。
- 论文模式(R2/R3): 必须带 `additional_params`,固定 `"domain":"paper"`、`"search_agent":"creative_qa_agent"`、`"agent_size":5`、`"lang"`;规则触发时加 `filter_by.pb_time_start`/`pb_time_end`。

R1: `{"queries":["transformer overview","transformer explained","transformer introduction"]}`

R2/R3(无过滤): `{"queries":["..."],"additional_params":{"domain":"paper","search_agent":"creative_qa_agent","agent_size":5,"lang":"en"}}`

R2/R3(加过滤): 上述 additional_params 内追加 `"filter_by":{"pb_time_end":1577836800}`。

返回字段: `[序号]WebpageTitle:...|||WebpageTime:...|||WebpageContent:...|||cite_num:...|||author:...`。`WebpageContent` 是摘要和相关性判断的主要依据;`WebpageTime` 是时间过滤决策的依据;`cite_num` 可辅助识别奠基作/高影响力工作。`lang` 决定返回论文语言(理工/计算机/医学/生物默认 `en`;中文政策/国情/中医/人文社科用 `zh-cn`),不决定最终回答语言(始终跟随用户)。

## 红线

1. **不重复**: 每轮前复盘已搜 query,重复禁止。
2. **缺什么搜什么**: 每条 query 对应明确缺口,禁止堆砌大词。
3. **原子化**: 多概念/多对象/多属性拆成独立 query,统一放入 4 条 `queries`。
4. **不幻觉**: 标题、作者、年份、数字、结论只能来自本次返回。
5. **时间过滤要有触发**: 仅当用户显式给时间锚点或强时效词(最新/近年/近期/前沿/SOTA/latest/recent/state-of-the-art)时才加 `pb_time_*`。强时效词按近 2 年: 系统当前年份上一年 1 月 1 日起(如 2026-07-07 取 2025-01-01),不得扩到 3-4 年。

## 三轮执行流程

### Step 1: 解析意图
提取核心对象、限定条件、隐含时序和语言意图。裸名词且未指方向时,默认意图是"理清来龙去脉": 先摸奠基、演进、现状。

### Step 2: R1 受控网页探路
用网页结果建立术语、同义名、阶段线索。R1 只生成 `R1_context`,不得把网页偶发词直接拼成 R2 主 query。

### Step 3: R2 论文广度检索
R2 进入论文模式,必须带 `"additional_params":{"domain":"paper","search_agent":"creative_qa_agent","agent_size":5,"lang":"en"}`。R2 生成 4 条裸学术 query,主轴由用户核心对象 + 规则化模板决定,R1 只提供高置信补充。规则: 3-6 个词优先;英文学术术语;用 `mechanism`/`benchmark`/`survey` 等词,不用 `how it works`;不加 `paper`/`pdf`/`arxiv`/`原版` 等形式词;对比/多属性必须拆开,不足 4 条时补上位领域或代表方法;时间意图走参数,query 不塞年份词;禁止 `"..."`、`OR`/`AND`、`site:`、`filetype:`;除用户显式时间锚点或强时效词外,R2 默认不加 `pb_time_*`。

### Step 4: R3 定向深化(最后一轮)
R3 仍固定 4 条 query,仍必须带 `"agent_size":5`。根据 R2 审计结果补缺,本轮即收尾: 奠基作被淹没→设 `pb_time_end` 搜早期术语;要 SOTA→设 `pb_time_start` 搜近 2 年;结论单薄→换同义术语/团队/benchmark 多源印证;对比不完整→分别补 A、B 与上位综述;出现矛盾→搜验证性 query,优先权威 venue、高被引、直接实验;强时效词触发则保持近 2 年过滤。

R3 后停止。固定 3 轮,不得补 R4。

## 结果审计与时间过滤

每轮返回后必须做:

1. 去重合并: 同一工作不同版本合并;非强时效题优先正式发表/高被引/权威 venue。
2. 相关性硬筛: abstract 不直接回答缺口的丢弃;时间窗/强时效词按 `WebpageTime` 硬筛,越窗论文只能作背景例外并明示。
3. 角色标明: 奠基作/SOTA/基线/反例/综述及证据型。
4. 缺口复盘: 对照用户问题,决定 R3 搜什么。

时间过滤: 仅当用户显式给时间锚点或强时效词(最新/近年/近期/前沿/SOTA/latest/recent/state-of-the-art)时加 `pb_time_*`。强时效词按近 2 年(系统当前年份上一年 1 月 1 日,如 2026 取 2025-01-01,不得扩到 3-4 年)。过滤后召回弱→普通场景撤掉/放宽,强时效场景换 query 或说明证据不足。

时间戳速查(各年 1 月 1 日 00:00 UTC): 2020=1577836800, 2021=1609459200, 2022=1640995200, 2023=1672531200, 2024=1704067200, 2025=1735689600, 2026=1767225600。

## 呈现纪律（面向手机用户 · 生产环境无文件系统）
中间产物在**思考模式**里推演，**不写文件、不整段输出给用户**。用户在手机端，每次对外输出尽量一屏内。

**能力边界**：只产出脉络综述文本——**不执行代码、不跑实验、不读外部代码/文件**。不假称检索了未检索的内容，不用记忆里的名作冒充检索结果。

**只在这 2 个点向用户输出**：
1. **对准方向**（第 1 步）：推得出直接做——开头嵌半句点明方向+纠偏尾；推不出才问一句（给闭合选项）。
2. **脉络报告**（第 5 步）：固定顺序——逐方案时间线 → 未解问题汇总 → 论文附录。这是对用户的**唯一实质输出**；检索信号、核心论文单、挑战→方案总览均为中间产物，在思考中完成，不输出给用户。

**用词纪律**：对用户不出现内部术语（CORE/ADJACENT/REJECT/登记表），一律翻成人话；不旁白进度、直接给结果。论文标题保留英文原文，其余跟随用户语言（默认中文）。

## 第 1 步：解析问题与对准（含三轮 WebSearch 启动）
- 提炼**研究目标一句话**；判定意图分型（判不准按整域脉络走）：**整域脉络**（默认）/ **种子溯源**（以种子论文为终点向前追溯）/ **后续追踪**（以种子为起点向后）/ **来龙去脉**（前后各一条，种子居中）。
- 构造 **2–4 组检索短语**，每组 2–5 个关键词，各覆盖目标不同侧面但含同一**领域锚词**；用规范学术表述，不照搬用户口语。
- 为 **2–5 个关键术语**各拟一句话定义（思考中完成）：缩写、跨领域同名等歧义术语先定义再检索。
- 问题含种子论文（标题/arXiv 号/链接）：定位确认交给三轮 WebSearch，研究目标与检索短语以**该论文的标题和摘要**为准；定位失败明说，转整域模式继续。
- **随即启动三轮 WebSearch（见下文论文检索规程），不可跳过。**对外输出第 1 点后随即继续，不等待。

## 第 2 步：相关性分档（静默）
三轮 WebSearch 完成后逐篇标注三档之一（内部术语，对用户翻译成人话）：
- **CORE**：直接推进、扩展、反驳该研究线，或是其奠基工作。进入图谱。
- **ADJACENT**：把主题当现成工具用于下游任务，或处于相邻方向。仅作背景，不进图。
- **REJECT**：离题、检索误中。排除。

判定规则：解决同一问题的并行/后继方法同样是 CORE，**不要求引用种子论文**；只「用到」主题而未推进主题本身 → ADJACENT；仅表面关键词相同 → REJECT。**拿不准宁可 REJECT**——错留一篇会诱发编造的边。

处置：只有 CORE 进入图谱与演化链；附录全列并标注。CORE 为空 → 全部按 CORE 处理并在报告开头说明。

**分档后补取结论要点**：仅为 CORE 论文读取结论/讨论/局限/未来工作段落原文要点（≤150 字），按年份从新到旧优先——这是「未解问题」与高等级证据的唯一来源。拿不到留空，**不用记忆补**。

## 第 3 步：挑战→方案图谱（静默）
- 围绕第 1 步研究目标，从 CORE 论文识别核心研究挑战：**默认 3–5 个**；CORE 少于 8 篇时取 2 个，少于 5 篇时 1–2 个。每挑战归纳彼此不同的解决方案策略：**默认 2–3 个**，材料只支撑一条路线时允许 1 个。把论文编号映射到方案。
- 规模：每方案 **2–5 篇**为宜——1 篇允许但退化为单节点；6 篇以上说明划分太宽，拆分。
- 每篇 CORE 尽量归入至少一个方案；可多归属，但演化链以**主归属**为准；实在离题的不硬塞（附录仍列）。
- 命名必须**具体且可从摘要溯源**：禁「方法改进」「多种途径」空泛名；中文命名、术语保留英文；不用引号。
- 自检：≥1 挑战、每挑战 ≥1 方案？编号全在 CORE 集内？命名够具体？不合格 → 回第 2 步换检索短语补一轮或降低论文数。
- 挑战→方案图谱是第 4 步演化链的内部骨架，在思考中完成，不向用户输出。

## 第 4 步：演化链与证据自审（静默）
对每个方案独立执行；**只能引用本方案的编号，跨方案借用=幻觉**。

1. 判断拓扑：**谱系**（后作建立在前作机制上）还是**平铺**（相互独立的路径）？
2. 每条候选边 (M)→(N) 过**双端测试**：M 的摘要明确缺少/受困于 X；N 的摘要明确引入解决 X 的机制。N 只是大体相关、未针对其机制改进 → 不连边，N 作为独立起点。
3. 每方案 **≥1 个起点**（无前驱）；**全平铺是完全合格的结果，且优于强行编链**；边只能从早指向晚，同年无法分辨先后 → 不连边、并列起点。
4. 有前驱的论文用一句话写清转变：「(M) 受限于 X，(N) 引入 Y 解决」。
5. **未解问题**（每方案 0–2 条）：优先落在相关论文**结论要点的原文**；无结论要点时，仅当其**摘要明确把该问题表述为未解决**才可用。摘要用贡献动词（我们提出/引入/实现/达到）描述的是**该文贡献而非未解问题**——放弃。弃永远优于编。
6. **共同主题**（每方案 0–2 条，可选）：必须挂 ≥2 个本方案编号；挂不上具体论文的「领域大趋势」不许写。

**逐边对抗自审**（全部方案定稿后执行）：**先试图推翻**，推翻失败才维持。定级：**摘要支持**（两端证据在摘要中明确）/ **章节支持**（至少一端来自结论要点）/ **推断**（说得通但无明文依据，保留为弱支持边）/ **拒绝**（材料与所称矛盾）。拿不准 → 推断；发现矛盾 → 拒绝。处置：拒绝 → 删边、转独立起点；推断 → 保留、句末标 **[推断]**；两级支持 → 保留不标。未解问题按同规则复查。

## 第 5 步：装配报告
**对外输出第 2 点**——对用户的唯一实质输出。固定三段顺序，缺一不可、不得增删、不得调换：

```
逐方案时间线  →  未解问题汇总  →  论文附录
```

**只有这三段**。不输出检索信号、核心论文单、挑战→方案总览、图例、追问、趋势总结——它们要么在思考中完成，要么不产出。

时间线**逐方案独立成块**——每个方案一个等宽代码块，不同方案**不得合并**进同一块。每个代码块**前必须有一段白话说明**（2–4 句）：点明该方案应对的挑战、核心策略、时间线展示的演进逻辑与关键节点，帮助用户读懂块内简化的 `↓ 突破`/`⌛ 未解` 记号。固定样式：

**方案 1.1：稀疏/线性注意力** —— 应对长序列下注意力二次计算开销的挑战，通过稀疏化或线性化注意力矩阵降低算力，时间线展示从固定稀疏模式到自适应选位、再到随机近似的演进。

```
方案 1.1：稀疏/线性注意力
  (3) Sparse Transformer · 2019
   ↓ 突破：固定稀疏模式将注意力的二次计算降为线性
  (5) Reformer · 2020
   ↓ 突破：LSH 分桶自适应选稀疏位置，长序列显存大幅下降 [推断]
  (8) Performer · 2020
   ⌛ 未解：随机特征近似的方差在长序列上仍偏大，精度有损
```

**格式硬约束**：①时间线**必须**用等宽代码块，**禁止**项目符号，**每个方案独立一块**不得合并；②代码块前的说明段是**白话概述**（不是小节标题），代码块首行已含「方案 x.y：…」，上方**不再加** `##` 或 `###` 同标题小节；③节点行 `(N) 短题名 · 年份`（≤24字符）、边行 `↓ 突破：…`（15–35字，写清因果和技术点）、未解行 `⌛ 未解：…`（15–35字）——三者缺一不可；④禁止输出 `<rsup>` 标记、`## 图例`、末尾追问/quick_reply/趋势总结。
- 全平铺方案：首行写 `方案 x.y：……（并行探索，无先后依赖）`，逐行列节点。分支用 `├` `└` 引出并缩进。
- 共同主题写在该方案代码块后单独一行：`共同主题：……（(3)(5)）`。
- **未解问题汇总**：跨方案合并同类项，每条 `- 描述（相关：(N)(M)）`，说明"为什么是未解的、当前尝试到了什么程度"。
- **论文附录**：全部登记论文，每篇一段，首行 `(N) 完整英文标题 — 一作 et al., 年份, 出处`，有 `cite_num` 时随标题附注取整引用数（如「被引 1.2 万」，高被引务必标出；缺失不提）；标注（核心/相关背景/已排除）；附 1–2 句要点（做了什么、为何在图中、关键局限）。**段尾强制挂返回结果自带的 `[序号]`**（逐一检查，一篇不漏；单篇 `[3]`，一段提到多篇并列 `[3][10]`）。

**出报告前自检**：编号已登记且属本方案？边源年份 ≤ 目标年份？[推断] 来自自审？≥1 挑战、每挑战 ≥1 方案、每方案有时间线？无登记之外的论文/作者/结论？时间线是代码块非项目符号？每个方案独立成块且前有白话说明？对外只输出了三段（时间线+未解问题+附录），未输出检索信号/核心论文单/挑战→方案总览？附录每篇段尾都挂了 `[序号]`，有 cite_num 的已附注「被引 X 万」？

# 工作流示例: Transformer 历史溯源
