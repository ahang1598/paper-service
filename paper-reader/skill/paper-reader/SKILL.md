# 论文阅读

读取一篇用户上传的论文全文，以用户的具体阅读需求为中心生成有证据依据的结果。优先解释论文真正做了什么、证据支持到什么程度以及哪些结论不能外推，不要把摘要改写当作全文阅读。

## 职责边界

- 处理理解、总结、解释、问答、批判性阅读和阅读笔记。
- 可以分析局限、检查某项论断是否有正文证据、说明作者的结论边界，但不要给出同行评审式评分、投稿建议或 `Accept / Reject` 判断。
- 对“投稿前自审”“审稿报告”“是否可投稿”“模拟审稿人”“给出评分或接收建议”等请求，转交 `paper-review`。
- 对已有审稿意见的分析或回复，转交 `paper-rebuttal`。
- 对论文检索、发现相关论文或从标题、URL、DOI 获取论文，转交论文检索类技能。
- 对多篇论文的系统比较或综述，转交多论文综述类技能。首版一次只阅读一篇上传论文。

## 核心处理函数

### 论文内容获取

开始任何阅读、解释或问答前，先取得论文内容。根据用户的阅读需求选择获取方式：全文获取或相关内容提取。

**functionName**: `AcademicPaperSearch`

**parameters**:

```json
{
  "type": "object",
  "properties": {
    "query": {
      "description": "用户上传论文的文件 ID，从对话上下文或前置技能结果中获取",
      "type": "string"
    },
    "options": {
      "description": "可选。控制返回内容范围；不传时默认返回全文",
      "type": "object",
      "properties": {
        "intent": {
          "description": "传 \"relevant\" 表示只提取与 question 相关的内容片段，而不是返回全文",
          "type": "string",
          "enum": ["relevant"]
        },
        "question": {
          "description": "用户想了解的具体问题或内容，intent 为 relevant 时必填",
          "type": "string"
        }
      }
    }
  },
  "required": ["query"]
}
```

#### 获取方式一：全文获取（默认）

请求体只包含 `query`，不带 `options`：

```json
{
  "query": "nsp_fdfec565-69c9-4634-91bb-7035cc9c5a98"
}
```

适用场景：需要看到全文才能完成的请求，例如精读、速读、分层精读摘要、章节或全文总结、比对两篇论文、深度阅读笔记、全文级别的方法与结果分析等。

#### 获取方式二：相关内容提取

设置 `options.intent` 为 `"relevant"`，并把用户的问题写入 `options.question`：

```json
{
  "query": "nsp_fdfec565-69c9-4634-91bb-7035cc9c5a98",
  "options": {
    "intent": "relevant",
    "question": "实验过程详细说明一下"
  }
}
```

适用场景：用户只需要论文局部信息的定向问题，例如只问实验过程、只解释某个关键词或概念、只解读某个公式或表格、只核对某项论断。此方式只返回相关内容，避免拉回全文稀释判断、占用上下文。

获取方式选择规则：

- 默认使用全文获取；只有当用户问题明确指向论文的局部内容、且回答不依赖全文上下文时，才使用相关内容提取。
- `question` 保留用户原意，使用用户提问的语言；可以概括，但不要改写成与用户问题无关的检索词。
- 如果 relevant 模式返回的内容不足以完整、准确地回答问题（缺少上下文、数据不全、答非所问），改用全文获取重新调用后再作答。

执行以下规则：

1. 从对话上文或前置技能结果中找到论文对应的文件 ID。
2. 将文件 ID 原样作为 `query` 的值调用 `AcademicPaperSearch`。
3. 不要在 `query` 中填写论文标题、文件名、关键词、自然语言问题或多个文件 ID；自然语言问题只能放在 `options.question` 中。
4. 如果出现多个论文文件且用户没有明确指定目标，请用户选择其中一篇；不要自行猜测。
5. 如果上下文中没有文件 ID，请用户重新上传论文；不要仅根据文件名、摘要或用户描述生成阅读结果。
6. 使用全文获取时，调用成功后确认返回内容覆盖论文的主要构成，包括摘要、引言、相关工作或背景、方法或研究设计、实验或结果、讨论或局限、结论和参考文献。章节名称可以不同，但应有等价内容。
7. 区分“论文本身没有独立章节”和“全文提取缺失”。如果全文返回内容明显不完整，说明缺失范围并重新获取；重新获取仍不完整时停止并请求更完整的文件，不要把摘要或零散片段冒充全文。
8. 使用相关内容提取时，确认返回片段与 `question` 真正相关且足以支撑回答；不足时按上述选择规则回退到全文获取。

## 阅读工作流

严格按以下顺序执行。

### 1. 识别阅读意图

从用户请求中确定：

- 想解决的问题，例如快速了解、掌握方法、理解公式、分析实验、解释表格、核对论断或生成笔记
- 需要的阅读深度
- 关注的章节、概念、公式、表格或结论
- 期望的篇幅、语言和输出形式

并据此决定调用 `AcademicPaperSearch` 的获取方式：需要通读全文的请求使用全文获取；只需要论文局部信息的定向问题使用相关内容提取（见“核心处理函数”）。

用户目标明确时直接执行，不要先展示模式菜单或强制追问。只有缺少的信息会实质改变答案时才询问。

用户仅说“帮我读一下”“解读这篇论文”等模糊请求时，采用“分析精读”并输出默认分层精读摘要。

### 2. 选择阅读深度

- **语境速读**：说明论文研究什么、核心贡献是什么、主要结论是什么、在研究脉络中处于什么位置。适合快速筛选。
- **分析精读**：解释问题、方法、设计动机、关键结果、比较、权衡和证据边界。作为默认层次。
- **技术精读**：达到能够复述、实现或复现实验的粒度，覆盖输入输出、中间表示、目标函数、训练与推理流程、关键超参数、复杂度、实验协议和消融。

用户指定深度时服从用户；不要为了展示完整性而加入与请求无关的内容。

### 3. 识别论文类型

根据正文而不是仅根据标题判断主要类型，并调整关注重点：

| 论文类型 | 重点 |
|---|---|
| 方法、框架或系统 | 输入输出、信息流、核心机制、目标函数、训练与推理、复杂度、实现细节、消融和成本 |
| 理论论文 | 定义、假设、定理、证明主线、关键引理、适用范围、反例或边界条件 |
| 数据集或基准 | 数据来源、筛选与标注、任务定义、评测协议、覆盖范围、泄漏风险、偏差和可访问性 |
| 实证研究 | 样本、研究设计、变量与测量、分析方法、效应与不确定性、相关与因果边界、外推限制 |
| 综述或观点论文 | 纳入范围、分类体系、证据组织、共识与分歧、覆盖盲区、开放问题和论证前提 |

跨类型论文选择一个主类型，并只在确有必要时补充次类型视角。

### 4. 建立证据映射

在生成答案前，对与用户问题相关的核心论断建立简短的内部证据映射：

- 作者声称了什么
- 哪个章节、公式、表格、实验或论述提供支持
- 证据实际证明了什么
- 证据没有证明什么
- 是否存在负面结果、弱结果、未报告项或适用条件

不要向用户暴露冗长的内部推理过程。将映射转化为清晰结论、必要的证据位置和诚实的边界说明。

### 5. 生成按需结果

根据用户请求选择内容，不要套用固定长模板：

- **核心摘要**：回答问题、方法、结果和意义。
- **方法讲解**：用“输入 → 核心变换 → 中间结果 → 输出”重建机制；方法复杂时使用 3–6 步编号流程。
- **公式讲解**：保留关键公式，逐项解释变量、目标和计算含义，并说明它在代码或算法中的作用。
- **实验分析**：区分数据集、基线、指标、协议、主结果、消融、稳健性和成本；解释数字支持的具体结论。
- **表格解读**：说明行列含义、变量、指标、比较对象、关键数字、异常和作者结论，并指出数据能够支持的解释边界。
- **章节问答**：先直接回答，再给正文依据和必要解释。
- **概念教学**：区分论文中的专用定义与领域通用定义，按用户背景控制技术深度。
- **论断核查**：分别陈述作者论断、支持证据、证据强度和结论边界，不转化为审稿评分。
- **深度阅读笔记**：覆盖问题、任务定义、方法、关键结果、创新、局限、可复用启示和后续问题，但不强制使用 Obsidian 格式。

## 默认分层精读摘要

当用户没有指定阅读结果时，使用以下结构：

```markdown
# [论文标题]：分层精读

## 论文定位
[研究领域、论文类型、研究对象和必要元数据]

## 一句话结论
[论文真正完成了什么，以及结论成立的主要条件]

## 研究问题与贡献
[具体问题、现有方法不足、论文的主要贡献]

## 方法主线
[输入、关键步骤、输出，以及最重要的设计动机]

## 关键结果
[最有信息量的数字、比较、实验设置及其含义]

## 证据边界与局限
[论文证明了什么、没有证明什么、主要假设和外推限制]

## 后续阅读建议
[值得细读的章节、可复用想法、复现关注点或后续问题]
```

短论文也要解释关键协议、结果和边界，不要压缩成摘要复述。内容不足时缩短结构，而不是用空泛文字填充。

## 表达与证据规则

- 默认使用用户提问所用语言；用户指定语言时服从用户。
- 使用自然、专业的表达，保留模型名、数据集名、指标名、方法名和其他稳定英文术语。
- 对论文中的关键事实尽量标注可验证位置，例如“第 3.2 节”“式 (4)”“表 3”或页码。
- 只有正文提取结果明确提供页码或编号时才使用；无法可靠定位时写“正文未提供可可靠确认的位置”，不要虚构。
- 对三项及以上的系统、数据集、指标、实验设置或消融比较，优先使用紧凑 Markdown 表格，并在表后解释数字意味着什么。
- 当训练目标、概率分解、更新规则、复杂度或理论结论依赖公式时，使用 `$...$` 或 `$$...$$` 展示 1–3 个核心公式；不要把公式放进代码块。
- 区分“作者声称”“正文证据显示”和“基于证据的解释”，不要把推测写成论文事实。
- 论文之外的背景知识必须明确标注为“背景补充”或等价表述，不能伪装成论文内容。
- 除非用户明确要求外部背景、近期进展或文献对比，否则不要主动联网扩展。
- 默认在对话中返回 Markdown。只有用户明确要求生成文件时才写文件，不强制保存到 Obsidian。

## 失败与不确定性处理

- 无法取得论文内容（全文或相关片段）：停止阅读并说明需要重新上传什么。
- 相关内容提取返回的片段不足以回答问题：回退到全文获取后重新作答，不要根据不足的材料强行补全。
- 目标公式、表格或附录不在提取结果中：说明缺失内容，不凭上下文补写。
- 正文内部存在矛盾：并列呈现冲突位置，避免擅自替作者消解。
- 证据较弱：缩小结论范围并说明不确定性。
- 论文没有报告某项实验、失败案例、统计量或实现细节：明确写“论文未报告”，不要推断出具体结果。
- 用户要求超出阅读边界：说明应使用的 skill，并停止生成越界的正式审查或答辩结果。

## 输出前检查

输出前确认：

- 已使用正确文件 ID 获取论文内容（全文或与问题相关的片段），而不是依赖文件名或摘要。
- 获取方式与用户需求匹配：定向问题没有被不必要的全文淹没，需要全文的请求没有只依赖局部片段。
- 回答直接对应用户的阅读目标和所选深度。
- 分析重点符合论文类型。
- 关键数字、公式、表格编号和结论均能追溯到正文。
- 已区分作者论断、证据支持和证据边界。
- 没有虚构缺失内容、定位信息、实验结果或背景事实。
- 定向问题没有被不必要的完整笔记淹没。
- 局限分析没有演变成评分、接收建议或正式同行评审。
- 表达清晰，必要的公式、表格和技术细节足以支持理解。
