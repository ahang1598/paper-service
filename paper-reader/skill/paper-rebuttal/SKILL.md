# 论文答辩回复

本技能提供一套系统方法，用于在收到同行评审意见后撰写答辩回复。目标不是为每一点辩护，而是通过解决真正影响评分的问题来推动分数提高。

# 核心处理函数

## 获取论文与审稿意见

开始分析或撰写回复前，必须先收集完整的论文和审稿意见。`AcademicPaperSearch` 同时支持读取论文文件和审稿意见文件，不要因函数名称中包含 `Paper` 而将其仅用于论文。

论文的获取方式：

- 从对话上文中找到论文文件对应的文件ID。
- 调用 `AcademicPaperSearch` 获取论文全文。

审稿意见支持两种获取方式：

- **对话来源**：用户直接在对话中提供审稿意见时，使用对话中的完整原文，无需为这部分内容调用函数。
- **文件来源**：用户上传审稿意见文件时，从对话上文中找到该文件对应的文件ID，调用 `AcademicPaperSearch` 获取完整审稿意见。

如果用户同时上传论文文件和审稿意见文件，必须针对两个文件ID分别调用一次 `AcademicPaperSearch`，获取论文全文和完整审稿意见后再继续。不得只读取其中一个文件，也不得将两个文件ID合并到一次调用中。

根据用户说明、文件名和返回内容区分论文文件与审稿意见文件。如果无法可靠判断文件用途，请用户明确说明，不要自行猜测。不得仅依据文件名、摘要、零散审稿意见或用户对论文的描述推断论文内容。

### 方法定义

**functionName**: `AcademicPaperSearch`

**支持的文件类型**:

- 论文文件
- 审稿意见文件

**parameters**:

```json
{
  "type": "object",
  "properties": {
    "query": {
      "description": "论文文件或审稿意见文件的文件ID（从对话上文中获取）",
      "type": "string"
    }
  },
  "required": ["query"]
}
```

每次调用函数时，将一个待读取文件的文件ID原样填入 `query`。`query` 中只能填写一个文件ID，不要填写论文标题、文件名、关键词、自然语言问题或多个文件ID。需要读取多个文件时，按文件逐一调用。

调用成功后：

1. 对论文文件，确认返回内容覆盖摘要、引言、相关工作、方法、实验、结论和参考文献等主要章节。
2. 对审稿意见文件，确认返回内容包含全部审稿人标识、评分、总体评价、优点、缺点、问题和修改要求；保留意见原意以及审稿人之间的归属关系。
3. 同时存在对话内审稿意见和上传的审稿意见文件时，合并两处内容并去除完全重复的意见，不得遗漏任一来源中的独有意见。
4. 将每条审稿意见与论文原文、表格和实验结果逐一核对，再开始诊断和起草。
5. 仅引用已在全文中核实的章节、表格、公式、数值和论断；不得编造定位或证据。

如果论文或已上传的审稿意见文件缺少文件ID，请用户重新上传相应文件；如果任一函数调用失败或未返回完整内容，明确说明缺失的是论文还是审稿意见及其范围，并重新获取。在取得论文全文和全部已提供审稿意见前，不要开始正式答辩，也不要生成声称基于完整材料的回复。

## 何时使用本技能

- 用户收到审稿意见，需要撰写答辩回复
- 用户询问如何回应审稿人的具体批评
- 用户希望在回复前从策略上分析审稿意见
- 用户提到“答辩回复”“审稿意见”“评审反馈”或“回复审稿人”


## 第 1 步：诊断审稿意见

动笔前，先回答：**“这位审稿人为什么给出这个分数？”** 不要只看他们写了什么，而要找出真正决定评分的原因。多数研究者会跳过这一步，对所有意见平均用力，这是错误的做法。

### 评分诊断

针对每位审稿人，思考：“怎样才能让这位审稿人从当前评分转向接收？”

| 分数范围 | 典型情况 | 应对策略 |
|---------|---------|---------|
| 7+ | 已经是你的支持者 | 为他们在讨论阶段提供有力论据 |
| 5–6 | 尚在观望，有 1–2 个顾虑阻碍其支持 | 找出并解决这些具体顾虑 |
| 3–4 | 存在根本性异议 | 判断异议能否解决；若不能，则将精力集中在其他方面 |

### 为每条意见标注颜色

通读每份评审意见，并为每条意见作如下标记：

| 颜色 | 含义 | 行动 | 预算 |
|------|------|------|------|
| **红色** | 决定评分的核心顾虑——这是低分的原因 | 优先处理，投入最大精力并提供证据 | 60% |
| **橙色** | 可解决的顾虑 | 用具体数据或修改来回应 | 30% |
| **灰色** | 次要或表面问题 | 简短确认并说明已修正 | 10% |
| **绿色** | 正面评价或赞扬 | 记录下来，作为支持者可使用的论据 | — |

### 找出隐含问题

每条审稿意见背后都有一个未明说的问题。例如，“基线已经过时”真正想问的是：“该方法与当前方法相比真的有竞争力吗？” 要回答隐含问题，而不只是满足表面要求。

## 第 2 步：规划回复策略

### 对每项顾虑分类

| 类别 | 回复策略 |
|------|---------|
| **误解** | 引用论文中的具体位置加以澄清，并重述关键观点 |
| **缺少实验** | 可行时直接在回复中给出实验；否则诚实说明限制 |
| **缺少基线** | 补充对比，或准确解释该基线为何不适用 |
| **表述不清** | 承认问题，并在回复中给出修改后的文字 |
| **根本性顾虑** | 用技术论证和补充证据直接回应 |
| **次要问题** | 感谢审稿人并确认已修正 |

### 找出共性主题

如果多位审稿人提出同一项顾虑，它几乎一定是真实的薄弱点。将这些意见合并到“共性回复”部分，既节省字数，也表明你已经理解各条意见之间的共同模式。

### 区分可操作问题与主观判断

- **可操作问题**：“缺少与方法 X 的比较”——可以直接处理
- **主观判断**：“创新性有限”——较难直接解决，但可以用证据重新界定问题

### 支持者策略

**答辩回复的真正受众不是持否定意见的审稿人，而是持肯定意见的审稿人。**

你的支持者会在领域主席（AC）讨论中替你发言，而且常常直接使用你的原话。撰写回复时要为他们提供可用的论据：

1. 让关键论点**可直接复制粘贴**——支持者可能会直接引用
2. 强调审稿人之间**意见一致的地方**——共识会增强支持者的立场
3. 指出**审稿人之间的矛盾**——如果 R1 认为“创新性有限”，但 R2 认为“思路有趣”，支持者便可利用这一点
4. **先讲优势，再讲不足**——提醒 AC 论文做得好的地方

## 第 3 步：撰写答辩回复

### 建立审稿意见分析表

动笔前，先用下表整理全部意见。每项顾虑只记录一次；若多位审稿人提出同一问题，在“审稿人”栏中并列标注，并将其作为共性问题处理。

| 编号 | 审稿人 | 顾虑（转述） | 类别 | 颜色 | 回复状态 |
|------|--------|-------------|------|------|---------|
| 1 | R1 | | 误解 / 缺少实验 / 缺少基线 / 表述不清 / 根本性问题 / 次要问题 | 红色 / 橙色 / 灰色 | 待处理 / 已起草 / 已完成 |
| 2 | R1 | | | | |
| 3 | R2 | | | | |
| 4 | R2 | | | | |
| 5 | R3 | | | | |

### 结构

1. **开场**：用一句话感谢审稿人，保持简短
2. **共性问题**：优先处理多位审稿人共同提出的问题，因为它们优先级最高
3. **逐位回复**：按优先级（红色 → 橙色 → 灰色）回应其余问题，**不要**按照审稿人的原始顺序处理

### 单项顾虑的回复格式

针对每项顾虑，采用以下三段式结构：

1. **确认理解**：用一句话表明你理解该顾虑
2. **正面回应**：给出答案，包括证据、澄清或新实验结果
3. **说明修改**：明确指出修订内容及所在章节或表格

### 18 条写作策略

#### 结构规则

**1. 先处理最重要的顾虑，不要按照审稿人列出问题的顺序回复。**
AC 会快速阅读答辩回复。把最重要的答案放在最前面，不要埋在次要问题之后。AC 首先读到的应该是你最有力的回应。

**2. 将共同顾虑合并到“共性回复”部分。**
如果两位审稿人都质疑基线，应写一份有力的统一回复，而不是两份较弱的重复回复。这样既节省字数，也表明你理解不同评审意见之间的共同模式。

**3. 简洁引用顾虑，然后直接作答。**
先给出答案，再补充支持细节。审稿人通常会略读，因此要把结论而非推理过程放在最前面。

**4. 使用以解决方案为导向的标题。**
写“澄清统计显著性”，不要写“提升是否具有统计显著性？”。问题导向的标题会让答辩显得被动防御，而解决方案导向的标题能传达信心。

#### 内容规则

**5. 直接行动，不要只作承诺。**
直接在回复中提供实验、解释或修改后的文字。“我们将在修订稿中补充”是最无力的回复。如果已经运行了新实验，就立即展示表格。行动比承诺更有说服力。

**6. 如果内容已在论文中，既要引用准确位置，也要重述内容。**
绝不要只说“如第 3.2 节所述”便就此结束。AC 在讨论阶段很可能不会重新阅读第 3.2 节。应在答辩回复中直接引用或概述相关内容。

**7. 用数据而非辩论来说服。**
一个新实验表格胜过三段解释。审稿人相信数字，而不是修辞。如果能在答辩期内快速完成实验，就去做。

**8. 保持回复自洽完整。**
AC 在讨论期间可能不会重读论文。应在答辩回复中重新介绍缩写、方法名称和关键设置细节，不要假设读者仍熟悉这些内容。

**9. 回应深层意图，不要只回答字面问题。**
“为什么没有与方法 X 比较？”通常意味着“我不相信你们的方法具有竞争力”。只解决字面问题，即加入方法 X，却不回应竞争力，就没有触及要点。应解决真正的顾虑。

**10. 绝不要引入新问题。**
答辩回复中的每个新论断都会成为新的攻击面。如果提到一项新能力，审稿人可能会追问“证据在哪里？” 应收紧范围，只为论文已有内容辩护，不要扩展论述边界。

#### 语气规则

**11. 从真诚的正面评价开始。**
例如，“感谢 R2 认可我们的方法能够很好地处理 X”，可以在进入辩护之前提醒 AC 论文的优势。这不只是礼貌，也是一种策略。

**12. 写“我们同意”，不要写“我们承认”。**
“承认”听起来不情愿，仿佛是在压力下让步；“同意”则显得协作而自信。细微的措辞会影响观感。

**13. 写“修订稿”，不要写“最终稿”。**
“最终稿”暗示论文已经被接收；“修订稿”尊重评审流程，显得更专业。

**14. 坦诚说明限制。**
如果因算力预算或会议页数限制而无法运行要求的实验，应如实说明。坦诚能够建立信任，沉默则像是在回避。大多数审稿人都能理解资源限制。

**15. 感谢审稿人提出有建设性的补充。**
如果审稿人发现拼写错误或推荐了有用的文献，简短回复“谢谢，已补充”几乎没有成本，却能增进善意。当审稿人感受到尊重时，也会更愿意接受你的论证。

#### 进阶策略

**16. 以专业方式指出不合理的评审意见。**
如果某位审稿人的顾虑与其他审稿人的意见矛盾，应客观说明事实：“我们注意到 R1 和 R3 都认为实验评估全面，这似乎回应了 R2 对评估范围的顾虑。” 绝不要攻击审稿人，让矛盾本身说明问题。

**17. 请同行检查关键回复。**
请同事核查最重要的 1–2 个答案。全新的视角可以发现逻辑漏洞、表述不清和证据缺失。虽然答辩期很短，但对答辩回复进行同行检查值得投入时间。

**18. 永久保存所有审稿意见。**
多次投稿中的规律会暴露你的盲点。如果三篇不同的论文都收到“创新性有限”的评价，问题很可能出在贡献的表达方式，而不是贡献本身。建立个人审稿意见档案。

### 字数优化

对于有严格字数限制（例如 500–1000 词）的会议，让每个词都发挥作用：

- **优先使用表格**：用紧凑表格展示新结果，通常比等价的文字说明占用更少字数
- **引用补充材料**：例如“完整消融实验见修订稿附录 A”，为关键回复节省字数
- **合并相关顾虑**：如果 R1 和 R3 都质疑稳健性，在一处统一回应，避免重复背景
- **将套话压缩为一句**：“感谢所有审稿人的反馈”已经足够，无需写整段致谢
- **使用项目符号**：比段落更紧凑，也更便于浏览
- **严格确定优先级**：如果 15 项顾虑中只能充分回应 5 项，就选择最可能推动评分的 5 项；深入回应 5 项胜过浅显回应全部 15 项

### 修订差异展示策略

同时准备修订稿与答辩回复时：

- **突出显示所有修改**：使用差异颜色；蓝色文字是常见惯例，便于审稿人快速定位
- **为修改编号**：在答辩回复中引用，例如“见修订稿中以蓝色标出的修改 3”
- **不要修改审稿人未要求的内容**：无关改动会引起怀疑，并产生新的攻击面
- **确保承诺与可见修改一一对应**：如果写了“我们修改了第 3.2 节”，修订稿中就必须清楚显示该改动

### 提交前检查

- [ ] 已用证据而非单纯论证回应所有标为红色的顾虑
- [ ] 已合并共性问题，没有在每位审稿人的回复中重复
- [ ] 关键论点可供支持者审稿人直接复制粘贴
- [ ] 已通过中立第三方测试：请一位没有读过论文的人只阅读审稿意见和答辩回复，并确认所有顾虑是否得到清晰回应；如果不能确认，就重写回复
- [ ] 字数符合会议限制
- [ ] 已在修订稿中突出显示所有修改并为其编号
- [ ] 没有引入缺乏证据的新论断

## 反直觉的答辩原则

1. **即使评分极端，也要提交答辩回复。** 分数为 3/8/8 的论文，机会可能比你想象的更大。持否定意见的审稿人可能会在讨论中意识到自己是异类，但前提是你提交了回复；没有回复，AC 就没有可用的论据。

2. **在小问题上让步，在大问题上取胜。** 承认一个次要弱点（例如“我们同意，为完整起见，表 2 可以加入数据集 X”），会让你对主要问题的辩护更可信。毫不让步的纯粹防御会显得不够客观。

3. **一个新实验胜过三段解释。** 审稿人受过质疑论证的训练，却不会同样质疑数据。一个直接回应顾虑的小型新实验，比再多推理都更有价值。

4. **最好的答辩回复写在投稿前。** 写论文时就针对可能的攻击拟好回复，即“预答辩”。这样做有两个好处：你往往会发现攻击确实成立并提前修改论文；如果真的收到该意见，也已有成熟的回复可用。

5. **不要平均用力地为每一点辩护。** 平均分配精力会暴露你不知道哪些问题最重要。根据颜色标注分配字数预算：红色 60%、橙色 30%、灰色 10%。审稿人能够看出你是否真正解决了关键问题。

## 常见审稿顾虑

提前为以下常见顾虑准备回复。准备好回复并不意味着逐字照搬，仍需根据具体论文和审稿人的具体表述进行调整。

| 常见顾虑 | 回复策略 |
|---------|---------|
| “创新性有限” | 阐明具体洞见；说明已有工作做不到什么；缩小并强化论断 |
| “提升幅度很小” | 强调其他优势，如速度、泛化能力和简洁性；增加更具挑战性的测试用例 |
| “缺少消融实验” | 直接在回复中提供消融实验表格 |
| “缺少基线” | 增加对比，或准确解释为何该基线不适用 |
| “无法复现” | 补充实现细节；承诺在明确时间发布代码 |
| “评估有限” | 增加多样化的数据集或指标；若不可行，诚实说明资源限制 |
| “未讨论局限性” | 在修订稿中增加局限性章节，并承认这是疏漏 |
| “结论夸大” | 弱化具体论断，使其与证据匹配；展示修改后的表述 |
| “比较不公平” | 采用标准评估方案；补充常用基线 |
| “该方法只是工程，不是研究” | 找出设计背后的科学洞见；解释该选择为何并非显而易见 |
| “指标与论断不匹配” | 将每项论断与具体指标对应；可行时补充缺失的指标 |
| “相关工作不完整” | 补充遗漏的参考文献；解释它们与你的工作的关系 |
