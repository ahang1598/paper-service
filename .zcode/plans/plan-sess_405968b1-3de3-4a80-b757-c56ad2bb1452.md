## 需求改写总结

将入参信封从 `{action, params, request_id, stream}` 改为 `{query, options, stream}`,路由路径与端口同步调整:

| 项 | 旧 | 新 |
|---|---|---|
| HTTP 路径 | `POST /api/v1/query` | `POST /api/v1/navigator/query` |
| WS 路径 | `WS /api/v1/ws` | `WS /api/v1/navigator/ws` |
| 端口 | 8000 | **12135** |
| 入参 | `{action, params, request_id, stream}` | `{query, options, stream}` |
| `query` | — | 原 `file_id` 的值(唯一必传项) |
| `options` | — | 可选覆盖项(默认 `{}`),允许覆盖 splitter/pages/with_rect/doc_hash/device |
| `stream` | HTTP 端被忽略 | **false(默认)→ HTTP 同步;true → 应改用 WebSocket**(HTTP 端对 true 主动拒绝并引导) |

**核心策略:在 schema 层做新旧格式转译,完全复用现有 `DocFullTextParams` 校验 + `DocFullTextHandler` + `DocFullTextClient`,业务逻辑零改动。** 单元/上游测试(60 个)不受影响,只更新 API/WS/验收层的 URL 与请求体。

## 改动清单

### 1. 新建 `app/schemas/navigator.py` — 新入参 schema
```python
class NavigatorQueryRequest(BaseModel):
    query: str = Field(..., description="文件ID(原 file_id),唯一必传")
    options: dict[str, Any] = Field(default_factory=dict, description="可选参数覆盖(splitter/pages/with_rect/doc_hash/device)")
    stream: bool = Field(default=False, description="false=HTTP同步(默认);true=流式,改用 WebSocket 端点")
```
内部转译函数:`query` → `file_id`,`options` 内容 → 剩余参数,组装成 `DocFullTextParams` 交给现有 handler。响应结构沿用旧 `{code, message, request_id, data}` envelope。

### 2. 修改 `app/api/v1/query.py` — HTTP 路由

- 入参改为 `NavigatorQueryRequest`;`stream=true` 时返回 400 + 引导信息("流式请改用 WS /api/v1/navigator/ws");`stream=false` 时把 `(query, options)` 转译为 `DocFullTextParams`,走原有 `handler.execute` 流程。

## 设计决策说明
- **HTTP 对 `stream=true` 返回 400 引导**:把 stream 字段从"被动忽略"提升为"主动路由语义",给调用方可编程的明确反馈,而非静默忽略。字段因此具有实际意义。客户端不传 stream(默认 false)不受影响。
- **不迁移路由文件到 `navigator/` 目录**:只改 APIRouter prefix,最小改动,降低风险。
- **不改变下游 client / handler / registry 业务逻辑、鉴权机制、响应 envelope 格式。**
